# 配置与运行约定

`project.json` 是可信的本地任务配置；`command` 能运行任意本地程序，执行器不提供代码沙箱。只运行自己理解或信任的配置。

## 字段

| 字段 | 约定 |
|---|---|
| `schema_version` | 当前为整数 1 |
| `name` | 项目显示名 |
| `inputs` | 每个会影响输出的文件，相对配置目录或绝对路径；不自动解析 Blender 外链 |
| `command` | 参数数组，禁止拼成 shell 字符串；每次仅输出一帧 PNG |
| `output` | 配置目录的相对路径或绝对路径；不能包含任何已声明输入 |
| `frames` | 闭区间 `[start, end]`，从正整数开始 |
| `image` | 实际像素 `[width, height]` |
| `fps` | 正数；当前编码器按该固定帧率编码 |
| `timeout_seconds` | 单帧进程硬超时，不是 ETA；默认 600 秒 |
| `poll_seconds` | 本地进程与空间检查周期，默认 1 秒；不是要求 AI 周期读日志 |
| `storage.reserve_bytes` | 输出所在文件系统运行时保留容量，必须大于零 |
| `storage.job_budget_bytes` | 启动额外余量；实际任务输出+临时数据预算，自行测算 |
| `content_check` | 可省略；仅支持显式校准的 `channel_presence` |

启动要求 `free >= reserve + budget`；运行中 `free >= reserve`。TEMP/TMP/TMPDIR 指向输出代次下的 `temp`。**只监测输出文件系统**，应用仍可能在系统盘写入它自己的缓存；已有多盘保护应保留。本工具不自动更改系统缓存、分页文件或软件全局首选项。

`command` 内的替换标记：`{python}` 当前 Python；`{project}` 配置目录；`{frame}` 帧号；`{output}` 待验证 PNG 路径；`{temp}` 任务临时目录。字面花括号写作 `{{` 与 `}}`。可执行文件建议加入 PATH，或在不提交的 `*.local.json` 中写绝对路径。

## 缓存与冻结

输入清单包括配置、声明文件的 SHA256、执行程序 SHA256、执行器 Python 源码哈希、Python 和 Pillow 版本。整个清单生成一个代次目录。新输入创建新代次，旧代次保留；首版保守地让所有帧失效，不做场景子依赖图推导。

未列入 `inputs` 的贴图、外部库、环境变量、驱动和系统字体等不会自动受跟踪。现有 `.blend` 使用外部依赖时，必须完整声明或预先打包验证，不能把这个工具的成功状态当成自动资产发现。

每帧经过：渲染至临时路径 → 完整解码和规则验证 → 再核对输入 → 原子移入帧目录 → 原子提交回执。崩溃发生在提交前的帧会重做；这比猜测孤立文件是否可靠更保守。已记录的坏帧被重做前会移入该代次的 `rejected`，工具不会自动删除旧代次。

有效帧每次恢复均重新解码/核对哈希。大型工程逐帧哈希输入有成本；首版以可靠、容易审阅为先，后续才考虑经验证的增量冻结索引。

## 恢复与状态

```sh
cg-workbench run project.json --wait-seconds 120 --max-recoveries 3
cg-workbench status path/to/output
cg-workbench verify project.json
```

空间不足默认立即返回退出码 2。提供 `--wait-seconds` 后，在这个**总等待预算**内等空间恢复；运行中触发保护最多恢复指定次数。每次重新启动仍做容量检查，未知错误和超时不盲重试。

退出码：`0` 技术检查通过；`1` 错误/验证失败；`2` 资源保护；`3` 主动暂停。`--max-new-frames N` 方便拆分执行。`--stop-file /path/STOP` 支持外部创建停止标记：当前子进程终止，完成帧保留；恢复前移除标记。

正常停止和超时会收回当前子进程树。操作系统强制杀死监督进程、断电或终端强杀不是正常停止；可能遗留应用进程，恢复前核实。文件锁在进程退出时释放，但不等于外部应用一定退出。

`state.json` 是最后写入的观察，`updated_at` 是心跳，不证明当前进程还活着。进程存在也不证明渲染正在推进。监督状态异常时，只看对应帧日志和资源证据。首版不发送桌面通知或远程消息，终端调用者负责消费退出码和状态。

## 内容检查

`channel_presence` 用 `roi` 内指定 RGB 通道达到 `min_value` 的像素数，与 `min_pixels` 比较。这是一个**供学习和固定镜头校准使用的简单规则**：蓝背景可能导致假通过，换灯/换镜头可能导致假失败。需同时提供正常/缺失样例证明适用性，不能泛称人物检测或质量评分。

## 对照与预览

```sh
cg-workbench compare before.png after.png comparison.png --crop 10 20 180 170
```

两张图尺寸须相同，裁切坐标相同，结果保持原生像素。输出旁的 JSON 记录源哈希；相机、光照、表情、帧与显示变换是否一致仍须核实。比较命令拒绝覆盖已有文件。

编码复用同时绑定帧回执和 FFmpeg 程序；重新检查视频尺寸/帧率/帧数/完整解码。编码后的美术与内容仍需审看，当前内容规则仅检查 PNG，不自动检查有损编码后的每一帧。
