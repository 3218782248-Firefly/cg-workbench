# 先让检查器面对真实错误

## 已有可运行回归

运行 `python -m unittest discover -s tests -v`。

| 故障 | 错误的成功依据 | 本仓库反例及预期 |
|---|---|---|
| 进程退出 0 但只输出第一帧 | 退出码 | `partial` 子进程不写第二帧；执行必须失败且保留第一帧 |
| 图损坏或尺寸不符 | 文件存在、扩展名 | 完整 PNG 检查与像素加载拒绝坏图，尺寸与契约比对 |
| 主体消失但图有效 | 全解码通过 | 全黑 PNG 通过技术检查；固定示例内容规则拒绝它，正常蓝色块通过 |
| 输入改变后复用旧成果 | 旧 state 显示完成 | 修改依赖内容后进入新代次；旧文件保留但不被当成当前结果 |
| 图被替换为另一张合法图 | 可解码即可复用 | 回执哈希不匹配，单帧重做；其他帧时间戳不变 |
| 空间不足或处理中跨过保留线 | 进程仍存在 | 注入磁盘读数，触发保护、保留回执；预算内容量恢复后接续 |
| 应用超时 | 再等一会或自动反复重试 | 真实慢子进程被终止，不把已有第一帧丢掉 |
| 用户停止后恢复 | 从头算最省事 | 真正运行的第二帧收到停止标记后退出，恢复复用第一帧 |
| 渲染期间修改输入 | 开始时冻结过就够 | 输入二次核对失败，候选图不提交 |
| 两个执行器同时运行 | 各有一个状态文件 | 输出根 OS 锁拒绝第二个执行器，进程退出后锁可重新取得 |

空间测试只模拟容量查询，不真的填满磁盘。主体检测用人造几何/颜色，不能据此宣称支持任意人物。

## 来自制作经验、尚未实现自动回归的案例

- **修改了被连线覆盖的默认值**：节点默认数值变了，最终输出没变。检查活动输入和上游连接，再用真实渲染判断；不能只读 UI 数字。
- **替换专用素材误删通用着色器**：先沿最终 Material Output 回溯活动依赖，并区分算法库与角色预设；节点名称和文件夹不是充分来源证明。
- **轮廓的小刺修后依旧存在**：比较同一工程、同一部位、同一像素尺度；区分几何/描边/纹理/透明排序，再按共用机制检查邻近部件。尚不确定时保留竞争解释。

这三项目前是诊断说明，不冒称 Blender 通用节点审计器已经完成。

## 怎样从一次漏检改善系统

先重新读取用户指出的实际产物，确认自己的检查是否看错来源、尺度或时间。写清“现象”和“原因猜测”；寻找能够区分主要解释的最小检查。原因成立后，沿共用材质、脚本规则、输入资产或时间边界扩大排查。

修复必须重新面对同一个反例，并检查该改动可能破坏的已认可性质。某个通用检查器抓不住错误时，补适用范围清楚的检查器或明确保留人工审看；不要改报告、放宽阈值或假设用户会继续找错。
