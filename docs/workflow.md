# 从制作目标到可交付结果

## 明确视觉目标，给技术路线保留选择空间

记录希望观众看到什么、必须保留什么，以及当前最主要的差距。参考可以是比例、眼神、发束叠压、线条节奏或材质关系。环境中的暖光、阴影数值不直接当成本征贴图颜色。

最有用的基线是用户认可过的具体画面与工程，同时记下认可范围。某个版本颜色较好不代表它的形状、细节和全部实现都应回滚。技术方法服务于目标；新方法应与基线公平比较，而非凭名称或复杂度采用。

## 先做能改变判断的小样

一般路径：参考与来源 → 资产导入 → 外观静帧 → 相关动态短样 → 冻结输入 → 可恢复渲染 → 按需后期 → 技术/内容/美术复核 → 采用与交付。

这不是每次必须重跑的清单。材质微调先比较同条件静帧；物理、闪烁、运动伪影才需要对应动态。已验证且依赖未变的检查可沿用。全局风格变化允许同时调整互相依赖的 UV、节点、法线和贴图，但结论应是组合方案的收益，不能虚称已证明某单一因素。

每轮有一个可描述的现象、可推翻的假设和能决定下一步的结果。发现主路线收益不明显时，检查输入/显示规则/控制通道/法线/采样等竞争原因；不要靠不断加深、提亮、堆细节或提高版本号证明进度。

## 工具成功与作品成功分别判断

1. **执行**：命令是否完成、应用是否报错。
2. **技术**：真实输出、依赖、帧数、尺寸、解码、音轨是否符合约定。
3. **内容与美术**：主体存在、边缘/遮挡/身份/动态、主次和原定风格是否保持或改善。
4. **采用**：是谁在什么范围确认该结果成为基线。

步骤不能相互冒充。全解码通过不代表角色没消失；对照图颜色接近不代表动作正常；几张静帧通过不等于全片实时审看。记录实际审过的帧/区间、尺寸、观看方式、发现与未覆盖范围。

## 正常执行由本地程序推进

把计算、校验、心跳和恢复放在可重复运行的工具中。AI 处理需要判断的画面、异常和交接；不需要为等待不断读取整个历史。预计耗时来自当前机器实测，初始化、计算、编码、验证分别估算；没有证据时不声称剩余百分比。

## 给下一部作品保留什么

保留可编辑基线、来源账本、配置与依赖、关键对照、采用决定和可运行恢复入口。项目最新入口只写当前结果、未解决问题与下一步；历史按需索引。失败经验保留能改变下一次行为的反例与适用条件，避免把每次事故扩成新的全局禁令。

耗时记录建议分为人工/模型判断、工具执行、GPU计算、等待和返工。Token 有可核验来源再记录，注明缓存和统计范围；不能由工具次数估算节约比例。
